# Verification — 0.2.0a2

Verified locally on macOS 26.4, Apple Terminal 2.15.

## Automated regression checks

58 tests passed across clipboard, native input/selection, composer, delivery,
presentation, responsiveness, file refresh, file tree and terminal onboarding.
Tests exercise SGR, X10 and rxvt mouse reports, forward/reverse selection,
Unicode, selection highlighting, no automatic copying, streamed replies during
selection, blank prompt separation, resizing, and agent switching.
Old presentation test assumptions were updated to the existing single-line
alphabetically sorted sidebar and Processes tab. No application behavior was
changed to satisfy those outdated assumptions.

## Actual Apple Terminal and macOS clipboard

Command:

```sh
swift tests/macos_clipboard_guard.swift /usr/bin/python3 -B tests/verify_native_terminal.py
```

The verifier opens a dedicated Apple Terminal window with an isolated demo,
sends terminal input using Terminal's AppleScript interface, and runs the real
curses input/render loop. It checks selection attributes in the curses screen,
clicks Copy via mouse reports, and compares actual `pbpaste` output exactly to
the selected fixture text. Forward and reverse multiline selections pass,
including åäö and 猫. No frame/sidebar content is copied. New replies render
after copying without restarting, and bracketed paste is accepted in the prompt.
The original clipboard items and all their stored data types are restored and
verified in memory. Clipboard contents are neither logged nor saved to disk.

Limit: mouse reports are injected through Terminal, not generated by physical
mouse gestures. OS-level Cmd+C and Cmd+V menu actions are not automated.
Accessibility automation is unavailable in this environment. The directly
verified clipboard path is selecting text and clicking the Copy button.

## Responsiveness

Same synthetic chat before and after: 120 messages, 12 lines per message,
12 streaming updates, cProfile enabled, fake screen to isolate formatting cost.
Median streaming render fell from 100.08 ms to 7.30 ms (about 93% reduction).
This measures rendering CPU cost, not end-to-end terminal or model latency.
The per-message cache retains only current item versions and is reset on
agent/width/view changes. Tests verify output equivalence and bounded entries.
Active chat snapshots are requested every 250 ms instead of every second;
sending or completing a command also wakes the polling thread.

## Files

A temporary real Git repository verifies that Codex completion schedules Git
collection, newly created files appear, and reverted/deleted untracked files
are removed from the result. Selected-folder refresh updates only the matching
agent and root. Git collection runs in the background, outside UI rendering.

## Installation

The wheel installs without network dependencies in an isolated Python 3.9
virtual environment. Version and noninteractive setup commands pass. Package
Python sources match the verified source files. The wheel contains application
files, generic demo data and package metadata, without personal state or
company-specific references.

Ghostty onboarding tests cover installed/missing cases, opt-in installation,
declining/default choice, no Homebrew, noninteractive mode and installation
failure. Homebrew itself is mocked: no terminal application was installed or
reconfigured during verification.

## Follow-up: replies hidden by a completed selection

A regression test reproduced a reply remaining invisible after mouse release,
until Copy cleared the selection. The renderer now freezes rows only during
an active drag; completed selections allow incoming replies to render. If the
selected source rows change (for example, retained history is trimmed), the
selection is cleared instead of highlighting or copying different text.

45 focused tests passed after this change (native clipboard, responsiveness,
presentation, clipboard, delivery and composer). The dedicated Apple Terminal
integration also passed with a reply injected BEFORE Copy: the reply became
visible immediately while the existing selection and highlighting survived,
and Copy still put the exact selected text into the real macOS clipboard.
The clipboard was restored afterwards. Physical mouse gestures remain outside
this automated check. This follow-up is in the source checkout; the previously
built distribution archive has not been rebuilt for this follow-up.
